## 一、進階功能測試

### 1.1 雲端儲存整合測試（S3 / GCS / Azure Blob）

#### 測試目標
1. **驗證連線能力**：確認 Label Studio 能正確連接到各種雲端儲存服務
2. **驗證資料讀寫**：測試從雲端儲存讀取資料作為標註來源，以及將標註結果寫回雲端儲存
3. **驗證權限控制**：確認憑證與權限設定正確運作
4. **驗證效能表現**：測試大量檔案讀寫的效能與穩定性

#### 測試方法

##### AWS S3 測試

**前置準備**：
```bash
# 1. 準備 AWS 憑證
export AWS_ACCESS_KEY_ID="your-access-key"
export AWS_SECRET_ACCESS_KEY="your-secret-key"
export AWS_DEFAULT_REGION="us-east-1"

# 2. 建立測試用 S3 Bucket
aws s3 mb s3://label-studio-test-bucket
```

**環境變數設定**（docker-compose.yml 或 .env）：
```yaml
environment:
  - STORAGE_TYPE=s3
  - STORAGE_AWS_ACCESS_KEY_ID=${AWS_ACCESS_KEY_ID}
  - STORAGE_AWS_SECRET_ACCESS_KEY=${AWS_SECRET_ACCESS_KEY}
  - STORAGE_AWS_BUCKET_NAME=label-studio-test-bucket
  - STORAGE_AWS_REGION_NAME=us-east-1
  - STORAGE_AWS_FOLDER=data
```

**測試步驟**：

1. **透過 UI 設定雲端儲存**：
   - 登入 Label Studio
   - 進入專案設定 > Cloud Storage
   - 選擇「Amazon S3」作為 Source Storage
   - 輸入 Access Key ID、Secret Access Key、Bucket Name、Region
   - 點擊「Test Connection」驗證連線
   - 點擊「Save」儲存設定

2. **透過 API 設定雲端儲存**：

    ```bash
    # 取得 API Token（從 Label Studio UI > Account & Settings > Access Token）
    export LS_PAT="your-jwt-refresh-token"
    export LS_TOKEN="your-api-token"
    export LS_HOST="http://localhost:8080"

    # 建立 S3 Source Storage
    curl -X POST "${LS_HOST}/api/storages/s3" \
      -H "Authorization: Bearer ${LS_TOKEN}" \
      -H "Content-Type: application/json" \
      -d '{
        "project": 1,
        "title": "S3 Test Storage",
        "bucket": "label-studio-test-bucket",
        "region_name": "us-east-1",
        "s3_access_key_id": "your-access-key",
        "s3_secret_access_key": "your-secret-key",
        "use_blob_urls": true,
        "presign": true,
        "presign_ttl": 3600
      }'
    ```

3. **測試資料匯入**：
   - 在 S3 Bucket 中上傳測試圖片（例如：`s3://label-studio-test-bucket/data/test-image.jpg`）
   - 在 Label Studio 專案中點擊「Import」>「From Cloud Storage」
   - 選擇已設定的 S3 Storage
   - 驗證圖片能正確載入並顯示

4. **測試資料匯出**：
   - 完成標註後，在專案設定中設定 Target Storage 為 S3
   - 匯出標註結果，驗證檔案正確寫入 S3 Bucket

##### Google Cloud Storage (GCS) 測試

**前置準備**：
```bash
# 1. 建立 GCP Service Account 並下載 JSON 金鑰
# 2. 將 JSON 金鑰檔案放在可存取的位置
export GOOGLE_APPLICATION_CREDENTIALS="/path/to/service-account-key.json"
```

**環境變數設定**：

```yaml
  - STORAGE_GCS_BUCKET_NAME=label-studio-test-bucket

```

**測試步驟**（類似 S3，但使用 GCS 設定）：
```bash
# 透過 API 建立 GCS Storage
curl -X POST "${LS_HOST}/api/storages/gcs" \
  -H "Authorization: Token ${LS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "project": 1,
    "title": "GCS Test Storage",
    "bucket": "label-studio-test-bucket",
    "project_id": "your-gcp-project-id",
    "use_blob_urls": true
  }'
```

### 1.2 ML 模型整合測試（預標註、線上學習）

#### 測試目標
1. **驗證 ML Backend 連線**：確認 Label Studio 能正確連接到 ML Backend 服務
2. **驗證預標註功能**：測試 ML 模型能自動產生預標註結果
3. **驗證互動式標註**：測試 ML 模型能即時回應標註者的操作
4. **驗證線上學習**：測試標註提交後能觸發模型重新訓練

#### 測試方法

##### 前置準備：建立簡單的 ML Backend

**使用官方範例**：
```bash
# 1. Clone ML Backend 範例
git clone https://github.com/HumanSignal/label-studio-ml-backend.git
cd label-studio-ml-backend

# 2. 建立簡單的影像分類 ML Backend
cd label_studio_ml/examples/dummy_model
```

**建立簡單的 ML Backend（Python）**：
```python
# ml_backend.py
from label_studio_ml.api import init_app
from label_studio_ml.model import LabelStudioMLBase

class SimpleImageClassifier(LabelStudioMLBase):
    def predict(self, tasks, **kwargs):
        """產生預標註結果"""
        results = []
        for task in tasks:
            # 簡單的預測邏輯（實際應使用真實模型）
            results.append({
                "result": [{
                    "value": {
                        "choices": ["Cat"]  # 預設標註為 "Cat"
                    },
                    "from_name": "choice",
                    "to_name": "image",
                    "type": "choices"
                }],
                "score": 0.95
            })
        return results
    
    def fit(self, annotations, **kwargs):
        """線上學習：根據新標註訓練模型"""
        print(f"Training on {len(annotations)} annotations")
        # 實際應在此處實作模型訓練邏輯
        return {"status": "ok"}

# 啟動 ML Backend
app = init_app(model_class=SimpleImageClassifier)
if __name__ == '__main__':
    app.run(host='0.0.0.0', port=9090)
```

**使用 Docker 啟動 ML Backend**：
```bash
# 建立 Dockerfile
cat > Dockerfile << EOF
FROM python:3.9
WORKDIR /app
RUN pip install label-studio-ml
COPY ml_backend.py .
CMD ["python", "ml_backend.py"]
EOF

# 建立並啟動容器
docker build -t my-ml-backend .
docker run -d -p 9090:9090 --name ml-backend my-ml-backend
```

##### 測試步驟

1. **連接 ML Backend 到 Label Studio**：

    **透過 UI**：
    - 進入專案設定 > Model
    - 點擊「Connect Model」
    - 輸入 ML Backend URL：`http://ml-backend:9090`
    - 勾選「Start model training on annotation submission」（啟用線上學習）
    - 勾選「Interactive preannotations」（啟用互動式標註）
    - 點擊「Validate and Save」

    **透過 API**：
    ```bash
    # 連接 ML Backend
    curl -X POST "${LS_HOST}/api/ml" \
      -H "Authorization: Token ${LS_TOKEN}" \
      -H "Content-Type: application/json" \
      -d '{
        "project": 1,
        "url": "http://ml-backend:9090",
        "title": "Simple Image Classifier",
        "is_interactive": true,
        "auto_update": true
      }'
    ```

2. **測試預標註功能**：
    - 匯入測試圖片到專案
    - 開啟任務進行標註
    - 驗證 ML Backend 自動產生預標註結果
    - 檢查預標註結果是否正確顯示在 UI 中

3. **測試互動式標註**：
   - 在標註介面中進行操作（例如：點擊圖片區域）
   - 驗證 ML Backend 能即時回應並提供建議
   - 檢查回應時間是否在可接受範圍內（< 2 秒）

4. **測試線上學習**：
   - 完成一個標註並提交
   - 檢查 ML Backend 日誌，確認 `fit()` 方法被呼叫
   - 開啟下一個任務，驗證模型預測結果是否有改善

**驗證檢查點**：
- [x] ML Backend 連線成功
- [x] 預標註結果正確顯示
- [ ] 互動式標註能即時回應
  - HuggingFaceNER 不支援 Interactive mode
- [ ] (?)標註提交後觸發模型訓練
- [x] 模型版本管理正常運作

**單一任務匯入**：
```bash

  -H "Authorization: Token ${LS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '[
    {
      "data": {
        "image": "https://example.com/test-image.jpg"
      }
    }
  ]'
```

**批次任務匯入（JSON 檔案）**：
```bash

  {"data": {"image": "https://example.com/image1.jpg"}},
  {"data": {"image": "https://example.com/image2.jpg"}},
  {"data": {"image": "https://example.com/image3.jpg"}}
]

# 匯入任務
curl -X POST "${LS_HOST}/api/projects/1/import" \
  -H "Authorization: Token ${LS_TOKEN}" \
  -H "Content-Type: application/json" \
```

**批次任務匯入（CSV 檔案）**：

##### 前置準備：產生測試資料

**使用 Python 產生大量測試任務**：
```python
# generate_test_tasks.py
import json
import requests
import time

LS_HOST = "http://localhost:8080"
LS_TOKEN = "your-api-token"
PROJECT_ID = 1

# 產生 10,000 個測試任務
tasks = []
for i in range(10000):
    tasks.append({
        "data": {
            "image": f"https://example.com/test-images/image_{i:05d}.jpg",
            "text": f"Test task {i}"
        }
    })

# 分批匯入（每批 1000 個任務，避免單次請求過大）
batch_size = 1000
headers = {
    "Authorization": f"Token {LS_TOKEN}",
    "Content-Type": "application/json"
}

start_time = time.time()
for i in range(0, len(tasks), batch_size):
    batch = tasks[i:i+batch_size]
    response = requests.post(
        f"{LS_HOST}/api/projects/{PROJECT_ID}/import",
        headers=headers,
        json=batch
    )
    if response.status_code == 201:
        print(f"Imported batch {i//batch_size + 1}/{(len(tasks)-1)//batch_size + 1}")
    else:
        print(f"Error: {response.status_code} - {response.text}")
        break

end_time = time.time()
print(f"Total import time: {end_time - start_time:.2f} seconds")
print(f"Average time per task: {(end_time - start_time)/len(tasks):.4f} seconds")
```

### 3.2 HTTPS/SSL 設定

#### 測試目標

2. **驗證 HTTPS 連線**：確認所有通訊都透過 HTTPS
3. **驗證憑證更新**：確認憑證能正確更新
4. **驗證安全標頭**：確認安全 HTTP 標頭正確設定

#### 測試方法

##### Nginx SSL 設定

**準備 SSL 憑證**：
```bash
# 將憑證檔案放在 deploy/nginx/certs/
cp cert.pem deploy/nginx/certs/
cp cert.key deploy/nginx/certs/

# 設定正確權限
chmod 600 deploy/nginx/certs/cert.key
```

**設定 Nginx SSL**：
```nginx
# deploy/nginx/nginx.conf
server {
    listen 443 ssl;
    server_name labelstudio.example.com;

    ssl_certificate /certs/cert.pem;
    ssl_certificate_key /certs/cert.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # 安全標頭
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;

    location / {
        proxy_pass http://app:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# HTTP 重定向至 HTTPS
server {
    listen 80;
    server_name labelstudio.example.com;
    return 301 https://$server_name$request_uri;
}
```
